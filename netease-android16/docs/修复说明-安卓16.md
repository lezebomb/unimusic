## 交付物

- 账号凭证备份：`账号凭证备份\MUSIC_U.txt`、`账号凭证备份\cm_cookie_storage.xml`、`账号凭证备份.zip`

## 为什么原来一装就闪退（真因，非架构问题）
1. 原包本身是 **LSPatch 0.6 二次打包**：`assets/lspatch/origin.apk` 才是真正的网易云主体，壳里还内嵌了 `com.raincat.dolby_beta`（杜比大喇叭 = UnblockNeteaseMusic）。
2. LSPatch 0.6 的实现用了 `android.app.ActivityThread$AppBindData#compatInfo` 字段，这个字段在 Android 16 已被移除 → 壳初始化直接抛 `NoSuchFieldError`，origin 的 dex 从未被挂上 classpath → 启动即 `ClassNotFoundException`。
3. 换 LSPatch 1.2（core canary-3106）壳就好了，但又撞上第二层：网易加固 `libpoison.so` 的**原生签名校验**。只要 APK 的签名不是荣耀原证书，它就在 dlopen 后 1~2ms 内用 `FORTIFY: pthread_mutex_lock called on a destroyed mutex` 触发 `SIGABRT` 自杀（伪造指针，拿不到 backtrace）。
4. `-l 1/2/3`（LSPatch 各级签名绕过）都挡不住：它看的不只是 PackageManager 返回的签名。删 `libpoison.so` 也不行——它的 native（`serialdata`/`deserialdata`/`ncaeDecrypt` 等）是整个 App 网络层的硬依赖。
5. 实验中发现一条关键事实：**把包名改掉（哪怕等长替换）也会触发加固自杀**，之前 user 10 沙盒里的崩溃大多是这种假阳性。

## 这次怎么修的
1. **LSPatch canary-492（1.2）+ `-l 0`（不做签名绕过）**：不碰签名校验路径，反而让 `libpoison.so` 正常加载（logcat 打印 `D/POISON: APK Signature:...` 后不再 abort）。
2. **自制 Xposed 模块（打进 dolby 模块的 classes2.dex）** 解决两个新问题：
   - 模块加载 `assets/lspatch/modules/.../lib/arm64-v8a/libdexkit.so` 时 `dlopen` 失败（APK 内 !/lib 路径 + isolated namespace）→ hook `System.load/loadLibrary`，把这些 so 解压到 `files/nativelibs/`，再用 `Runtime.load0(模块ClassLoader, path)` 预加载，让 `JNI_OnLoad` 用模块的 classloader 找得到 `DexKitBridge`；
   - 同一个 hook 里，**其它所有 so 一律走 App 自己的命名空间**（`Runtime.load0(CloudMusicApplication, path)`），否则 Xposed 调原件会让调用方退化成 boot classloader → `libpoison.so`/`libxcrash.so` 落在 `com_android_art` 命名空间，报 `library "libstdc++.so" not found`，启动卡死在 splash。
   - 另把模块的 `CLASS_*` 空值守卫住（模块以前会 `findClassIfExists("")` 抛 `Class name is empty`，把后续 hook（含 UNM）整条注册链打断）。
3. **`origin2.apk`**：往原版 `origin.apk` 的 `lib/arm64-v8a/` 里补了 `libnode.so`（30MB）和 `libdexkit.so`，因为模块是拿 `nativeLibraryDir/libnode.so` 当可执行文件 `sh` 起来的（`libnode.so app.js -a 127.0.0.1 -o pyncmd kuwo`）。缺它 UNM 服务起不来。
4. **自动登录**：hook 在 `attachBaseContext` 阶段把备份的 `MUSIC_U` 等 cookie 写回 prefs+mmkv，卸载重装也不用再输手机号。
