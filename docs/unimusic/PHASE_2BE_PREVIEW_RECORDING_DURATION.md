# Phase 2BE：试听时长与逻辑录音元数据分离

已知歌曲时长原本不会被播放器覆盖；但当SongItem时长未知时，初播/刷新和时间线回填会把实际媒体时长写回队列/当前歌曲。明确20秒试听因此可能变成错误的“完整录音时长”，使后续按严格时长门槛匹配真正完整来源时被拒。

现在解析结果明确试听时只更新当前传输/进度时长；未知逻辑时长保持未知，不写队列或持久状态。初播、刷新分别传递资格，时间线回填根据当前候选和音频信息再次复核。后续真正完整结果仍可回填未知元数据，普通20秒完整短歌照常处理。已有正确长曲元数据保留；不按长度猜测或批量擦除旧歌曲，以免误改短歌。

新增2项/共3项直接相关JVM通过：显式结果和后续时间线都不把试听写成未知录音时长，未知试听→完整录音可正确回填，已知元数据不被试听覆盖，正常20秒完整短歌及原有回填行为保留。Debug48s、模块边界通过。
