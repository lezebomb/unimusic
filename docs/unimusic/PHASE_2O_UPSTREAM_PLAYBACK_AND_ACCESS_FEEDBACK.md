# Phase 2O：对照音理音理原版与明确取流反馈

日期：2026-10-27。基线 `f17094dc`，Room 仍 v23；没有改动迁移、账号或歌单数据。

## 原版参考

本轮从 Git 历史读取原始 NeriPlayer 基线 [`b9b6caf3`](https://github.com/cwuom/NeriPlayer/tree/b9b6caf39bc65ca252f1c6a632ec24320cec68bb)，并 fetch 核实最新 master [`0d9ce69f`](https://github.com/cwuom/NeriPlayer/tree/0d9ce69fae19c371ec2e23d0dd6fc86b5a2b589b)。仅对照源代码，没有把上游数据库、UI 或账号存储整包合并，也没有覆盖安装原版 APK。

原版的重点是启动时并行预热网页会话、bootstrap 和 player.js/EJS，再让按需播放认领队列预取；多客户端、音频质量、签名失败及缓存回退仍有用。当前项目保留了这些机制，最新上游的 YouTube 改动主要在账号持久化，没有新的取流协议可以直接替换。

原版签名竞速解析窗口为 12 秒。2N 新设共享任务 8 秒可能先于它结束，因此本轮分开预算：明确选择 YouTube 播放时主解析最多 20 秒，后台共享解析最多 30 秒，已有自动切源/其他主源仍为 8 秒；嵌套 YouTube 解析不得延长已有短期限。UUID 入口扣除读库时间后再给主源剩余预算。单次文本 HTTP 仍为可取消的 3 秒，bootstrap HTTP 加载仍为 8 秒，保留取消与隐私修复。这是冷启动兼容修正，并非宣称实际冷签名已经成功。

## 实际失败定位与优化

按原版 `warmBootstrap → getBestPlayableAudio` 路径运行当前真实 Kotlin 仓库，保留正常 HTTP/解析器，仅加入不含请求内容的状态诊断。主页与 player.js 均正常返回 HTTP 200；各客户端取流响应却是 UNPLAYABLE / LOGIN_REQUIRED，音频格式数量为 0。由此确认这组匿名样本有明确平台拒绝，不能把所有失败都归咎于超时或 JavaScript。

原先没有成功响应时会再刷新 bootstrap、重复客户端，并进入匿名 extractor。现在仍完成一轮正常客户端/locale 回退，只有无登录 Cookie、所有响应均为已知明确拒绝、没有成功或网络错误时，才结束重复尝试并返回类型化状态。有登录态、未知状态、网络故障或任何 OK 响应仍保留原版恢复逻辑，避免误伤正常签名/客户端回退。

运行时将登录拒绝映射为 RequiresLogin，来源校验保留 AUTH_REQUIRED；普通界面明确提示 YouTube 登录验证或内容不可播，并给出设置登录/选择其他来源的去向。不可播放内容单独提示。拒绝结果不保存为全平台结论，不把登录描述为保证可播。

## 验证

9 个定向 JVM 检查通过：3 个匿名拒绝/恢复检查、3 个原取流及共享/签名回退检查、3 个共享预算检查。新预算的虚拟时间检查证明直接播放可以完成 12 秒准备、嵌套自动回退仍在 8 秒结束。只重跑修正过的测试类，没有完整重跑上游。

最终 APK/测试包构建成功、平台依赖和模块边界通过，并保留数据安装到 Mate60。首次边界需精确登记三个新类型；测试曾误把两个共用 client ID 的 TV 版本当重复请求，改为 ID+版本后通过。诊断中可选 sandbox 字段缺直接测试依赖，已移除，没有增加无关依赖。

真机播放验证仍未通过：诊断前 1 次、最终 2 次均没有返回音频地址。最终生产播放器在本次约 5818ms 收到 LOGIN_REQUIRED，pending=false，观察末相关 HTTP Call 为 0；最终预热诊断为一轮 6 次 player 响应、0 音频格式，4958ms 返回明确登录拒绝，前次是 12 次 player 响应并重复 bootstrap。查询返回和缓存未完全控制，不做首声、百分比或分位数性能结论。

正常 App 界面也实际确认了新的 YouTube 登录提示，随后关闭对话框并暂停播放。现有网易云登录和两份 5 首歌单保留；本轮没有新短信、Google 登录或 Gmail 连接，QQ 正向账号取流仍待验证。不能把 9 个单测通过当作 YouTube 播放成功。

原始输出、XML、APK 哈希与未测项见 [validation.json](evidence/2026-10-27/phase2o/validation.json)。上轮 [2N CI](https://github.com/lezebomb/unimusic/actions/runs/40468361983) 已成功。

下一步需要真实 YouTube 官方账号验证或其他可用来源；即使登录，曲目/网络可用性仍需实测。继续保留原版正常客户端与预热路径、精确录音门槛，不用绕过授权来把失败标成成功。
