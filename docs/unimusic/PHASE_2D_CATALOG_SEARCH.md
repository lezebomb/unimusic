# Phase 2D：目录搜索接入与排名修正

日期：2026-10-26。接续 `b6a67864`，该提交的 [远端 CI](https://github.com/lezebomb/unimusic/actions/runs/40276481535) 已成功。Room 保持 v22，没有迁移、删除或改写用户数据。

## 现在可用的行为

- 默认聚合搜索在原有本地/网易云/B 站/已开启的 YouTube 之外，接入已实现的酷我目录 Provider。酷我沿用独立游标、超时和失败状态，不影响其他来源的结果。
- 新增 `ExploreSearchResult.Catalog`，保留完整来源键。目录结果不转换为 SongItem，混合列表中的播放队列仍只从 Song 类型生成，因此酷我数字 ID 不会误当成网易云歌曲 ID。
- 目录行显示歌曲、歌手/专辑、时长、占位封面及“酷我 · 仅歌曲信息”；只提供用户主动点击的“在酷我查看”，没有播放、收藏、下载或加入队列动作。补齐中文/英文文案和来源状态。
- 外部打开严格限制为该目录条目对应的 HTTPS 官方页面：`www.kuwo.cn/play_detail/<规范正整数 ID>`。拒绝其他协议/主机、用户信息、查询、片段或不同歌曲路径；打不开时提示，不自动跳转或偷偷获取音频。
- 目录与播放能力继续分离。搜索到歌曲、打开官网不代表已拿到完整音频或获得播放权限；本轮没有增加酷我音频解析。

## 搜索与自动候选修正

1. **修复全角版本漏判。** 原 versions() 直接匹配原文，canonicalTitle() 却先做 NFKC，因此 `晴天（Ｌｉｖｅ）` 可能在标题被规整后误通过原版门槛。现在标题/上下文先统一 NFKC，再识别版本；回归覆盖全角 Live/Cover/Remix。修正同时用于本地兜底、B 站自动匹配和搜索排序。
2. **将聚合排名移出主线程。** 在 Dispatchers.Default 上计算各批次排名，返回主线程后仍验证请求 generation，旧请求不能发布排序结果。
3. **单次查询缓存排名。** 最多保留 2048 个条目的文本分数与版本差异，键为来源稳定身份，并核对完整结果数据；元数据编辑时重新计算。新查询或账号/开关变化会创建新 ranking session，不保存凭据或媒体 URL。缓存大小不是搜索结果数量限制。
4. **版本偏好不盖过曲名相关性。** 原按版本惩罚优先排序，可能把歌手叫“晴天”的其他歌曲排在《晴天 Live》之前。现在版本差异只作有界展示加分；保留已有曲名/歌手/专辑权重、拼音与多词匹配。分数相同才优先已有播放路径的 Song 结果，目录条目仍保留且不跨平台合并。

排名只决定发现顺序，不产生经校准的同录音概率，不放宽真正播放前的版本/分 P/时长和接口访问校验。
