# Phase 2H：共享解析预算与保守原唱匹配

日期：2026-10-27。用户要求失败切源尽快返回，并明确排除翻唱/混剪等错误音源。本轮先阅读真实调用链再修改；没有将配置时限当成实际延迟测量。

## 搜索与切源的不同等待

聚合列表原先就按来源并发、分批返回，每来源预算6秒（含排队），一个失败不会阻塞其他已返回结果。本轮Explore的并发数从3改为4，使本地索引及网易云/B站/启用YouTube这四个可播放来源同时启动；酷我仍是仅目录的第五来源，按空余名额处理。每来源仍只启动一个首批搜索任务，未增加同平台的大量并发。

原点播路径为人工首选8秒、网易云主源8秒、自动B站10秒等独立预算，可能叠加到十几秒甚至更久。本轮以协程上下文保存同一次解析的单调时钟截止时间：

| 阶段 | 在共享请求中的分配上限 |
| --- | --- |
| 整体地址解析 | 8秒共享协程预算 |
| 人工首选 | 2秒总预算，每候选1.5秒 |
| 网易云主源 | 2.5秒总预算，每次音质请求1.5秒 |
| B站备用 | 最多5秒且不超过剩余时间，每候选1.8秒 |
| B站元数据召回 | 两个关键词并发，各最多1.5秒，仍计入共享预算 |

遇到明确错误会提前结束该尝试，不固定等满时限。递归恢复和下一阶段不能重新获得8秒，父级取消继续传播；已有失败冷却仍保留。显式的单来源校验没有额外缩短，沿用其自身8秒边界。解析超时会显示明确提示，旧请求和后台预取不会弹出该错误。

8秒是地址解析协程预算，**不是点击到出声的硬性保证**：播放器连接/缓冲/启动和运行期卡顿检测是另外的路径，上游阻塞式提取器/传输能否及时取消也需实测。现有启动早期检测5秒、普通远端10秒、YouTube25秒，以及运行期4/8/12秒等策略未在无设备证据时盲目调整；不能把本轮改动称为所有故障均8秒内完成切换。

## 原唱/版本安全

- 继续NFKC、大小写/装饰规范化；标题、歌手和已知时长分别检查，在线播放匹配通常允许4秒差异，本地8秒；元数据缺失不自动通过。
- Live、翻唱、伴奏、Remix、变速、剪辑、重制和重录与目标版本冲突时拒绝。本轮补上教学/教程/讲解、tutorial/lesson/reaction等标签，防止分P标题干净而视频上下文实际为教学。
- 首次B站自动切换不再只因标题提及原歌手而填入自动可用候选。搜索上传者名称须与歌手规范化后完全一致，获取视频详情后再次核对；随机搬运/翻唱者的标题提及不够，仍可在菜单中人工选择。
- 两个召回查询合并后，严格元数据门槛通过的不同上传候选超过1个，或没有完整合格候选时，不使用文本分数强行挑第一个；保留供来源菜单人工选择。该唯一性仅针对已召回候选，不是互联网全量证明。自动多P合集召回会更保守，手动精确CID选择仍保留。
- 人工确认/拒绝、临播重查版本/权限、精确aid/cid与在途revision复核继续保留；人工确认不能取消版本和权限门槛。

上传者同名仍可能是假冒，标题/歌手/时长可能被误标；目前没有官方账号ID与艺人身份的可信绑定、音频指纹核对或真实人工标注集校准。因此本轮是降低常见错配风险，不能承诺100%原唱或错误率低于1%。更严格自动筛选会降低自动命中率，证据不足时优先让用户确认。
