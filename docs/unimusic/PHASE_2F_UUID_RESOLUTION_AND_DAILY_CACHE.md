# Phase 2F：UUID 临播适配、四源候选和每日快照

日期：2026-10-27。接续10月26日暂停前工作区。本轮只做直接相关检查，不重装工具链、不重做历史迁移。

## UUID 与实际播放

新增 UnifiedPlaybackBackend/RoomStore 的精确 UUID 反查：优先读既有桥接所指向的当前 durable SongItem，保留自定义字段及队列身份，去掉瞬时 streamUrl；无旧 track 时仅从精确的网易云/B站/YouTube ID 恢复兼容引用。不按同名合并；B站 cid 保持独立；未知或仅目录 UUID 不猜测音频 URL。

现有 resolveSongUrl 兼容入口先取得真实统一 UUID，再进入原播放器路径。新增 resolveUnifiedSongUrl(UUID) 入口；匹配读取同时核对 UUID 与旧稳定键，避免把另一个逻辑录音的人工决策套到当前队列。没有可用投影时保留原有播放器路径。原UI/队列仍是 SongItem，不把适配器标成整个音乐库和同步都已切换UUID。

人工确认源临播重新读取元数据和正常播放API。网易云新详情同时检查专辑及 alia/alias/tns/transNames 的版本标签；YouTube检查新标题/作者及实际音频时长；B站重新检查视频/分P/完整播放信息；本地文件重查权限与可读性。解析前后对账号和YouTube开关做内存会话复核，旧授权结果不应用到新会话，决策revision/目标指纹继续复核。没有新增播放授权或独立权利注册表。

修复预取交接的两处问题：后台为下一首解析来源时，不清除当前曲目的B站跳过区间；清除动作同时核对歌曲和播放请求token。人工匹配/B站自动替代URL不经旧预取直接交接，必须重新解析，避免预取后拒绝、清除或换号被缓存绕过；本地自动兜底继续沿用原有可读性及匹配复核。

## 四源菜单

来源菜单元数据发现扩展为本地、B站、网易云、已启用YouTube，每来源独立预算/失败状态、有限候选、全量分P检查后排名。网易云沿用现有登录门槛和可取消搜索；YouTube关闭时停止查询和确认，但仍可清除/拒绝旧记录。三平台账号/开关变化使旧请求失效。元数据缺失不拿查询词补歌手/时长，不批量解析音频URL。酷我仍仅目录，未接入音频。

YouTube的bootstrap/search/browse共用文本传输及oEmbed改用可取消OkHttp调用；协程超时会取消底层请求，避免界面已超时而旧HTTP继续占用来源预算。没有改变请求内容、重试权限规则或播放器签名流程。

## 每日推荐快照

推荐日期及排序统一使用北京时间自然日。私有JSON缓存只保存日键、模式、算法版本、旧稳定键的SHA256摘要、实际已桥接UUID、理由及来源；不保存完整SongItem、路径、URL或凭据。使用Mutex/现有原子写和32KiB预算，损坏/未知版本/IO失败安全降级。

同日统计变化保持推荐顺序，显式刷新和北京时间午夜重建；恢复时读取当前音乐库元数据/播放引用，删除项即时过滤。正常缓存命中不重复读512条统计进行排名。未桥接记录UUID为null，不凭空生成；尚未实现独立负反馈事件或推荐/人工映射跨设备同步。
