# Phase 2BV — B站分P录音元数据一致性

2026-10-30（Asia/Shanghai）。设备发现 `原曲` / `On Vocal` 分P被直接当歌名，无法和父视频声明的歌曲匹配。

来源发现、严格CID选择和实际播放描述共用页元数据函数。明确的 `On Vocal` / `原曲` / `原唱` 页可取已核对父视频标题；多分P的 `P1`、`Vocals` 人声分轨和其他不明名称不能借父标题。保留搜索标题、父标题、分P与上传者中的翻唱/AI/伴奏等负面版本证据，只用当前分P的时长；多个同样合格的页仍拒绝自动猜选。

账号/决定/网络复核、预览/DRM检查、实际音频时长核对及自动切源上传者署名门槛没有放宽。此改动不证明候选是真实原唱，也不会把普通上传者自动提升为歌手账号。

累计完善4P：Library/SourceChoice的初始YouTube启用值同时核对来源注册表，Home观察器也先查注册表，避免启动时旧内存默认true提前打开停用仓库。

实际：Debug首批2m10s、补齐初始启用守卫后49s构建通过，边界通过；只准备最终包安装，没有为中间包装机。新增2项直接针对CID/原唱与伴奏/版本污染/缺失页时长的runtime回归，按现有CI选择器执行；本机无JDK21，未下载或重试该模块JVM。设备与CI结果在续跑检查点追加，不能以编译成功代替播放或新用例通过。
