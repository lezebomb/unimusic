# Phase 2E：持久来源选择、导入操作与本地推荐

日期：2026-10-26。沿用播放器/安全账号/导入后台；本阶段加入可操作入口，不重写旧歌曲身份和队列。

## 持久来源决策

- Room 22→23 只增加 `song_match`、`user_match_override` 两表及索引；已发布的 20→21、21→22 保持原样。观察与人工决策分表，使用 Upsert，避免 REPLACE 删除引用。
- 目标通过既有 legacy link 对应真实统一 UUID；候选保存 provider/resource/sub-resource 和元数据/算法版本/目标指纹，不保存音频 URL、Cookie 或本地路径。确认是录音映射，不授予播放权限，也不合并两个既有 UUID。
- REJECTED 经磁盘重开仍有效；后台观察不会覆盖人工决策。确认时继续要求标题/歌手/时长/版本一致；编辑目标元数据后旧确认失效，后台不能偷偷重新确认。
- 清除决策保存 NONE + 增加 revision。网络解析完成后重新核对 revision/状态/目标指纹，防止请求中途拒绝或清除后旧结果生效。
- 自动网易云→本地/B站路径使用相同拒绝记录；本地候选仍须权限及可读性检查，B站重新读取视频/分P/完整播放信息，不允许试听或 DRM 内容冒充完整音源。

## 操作入口与实际播放

- 播放页更多菜单新增来源选择。元数据发现目前只查询本地文件和 B站，不提前获取音频 URL。每来源 8 秒预算，最多 3 个 B站详情并发；全部有效分P先匹配排序再限制展示，确认绑定精确 aid/cid。
- B站搜索 JSON 业务错误现在抛出失败，使界面区分暂无候选与读取失败。B站会话变化会取消旧请求并清空候选。
- 确认来源影响下次解析：现有播放器优先尝试当前有效的人工记录，临播重查权限/版本/真实可用性；失败后保留原解析路径。当前菜单仅发现本地/B站；解析适配器也支持已有网易云/YouTube精确记录，不宣称菜单已覆盖全部平台。
- 切源缓存键属于实际来源，逻辑队列/收藏仍用原歌曲；原 B站视频的跳过区间不套用到另一个录音。真实启动/卡顿失败进入短期冷却。
- 当前入口仍以 SongItem 兼容适配工作，独立 `SourceResolver(unifiedSongId)` 与跨设备决策同步留给后续阶段。

## 导入界面

音乐库顶栏可按公开用户 ID/当前登录账号列出歌单，多选一次导入或保留关联。复用已有持久任务、失败分页、取消/重试、显式刷新和解除来源；批量提交与任务变更互斥，防止取消后又被同批提交恢复。目标歌单被删时明确该任务不可继续，不承诺无效的重新导入恢复。关联目前仅手动刷新。

## 本地推荐初版

首页增加独立 UniMusic 本地推荐栏目，保留平台栏目。根据现有本地/导入歌单、近期256和常听256条真实统计进行确定性规则排序，包含艺人亲和、时间衰减、近期重复降权、探索和艺人多样性，显示理由/来源并支持离线本地候选。没有统计的歌曲代表未知，不伪造跳过/完成/不喜欢。首页无订阅5秒后停止观察和重排；当前尚无每日持久快照或显式负反馈。

## 验证与限制

32 个定向 JVM 测试通过。实际命令、JUnit XML 和产物哈希保存在 `evidence/2026-10-26/phase2e/validation.json`。重点验证冻结 v22 所有原表逐字段保留、磁盘重开人工拒绝、编辑目标后旧确认失效、catalog不能确认、导入任务约束、推荐排序及精确分P选择。只执行与改动相关的定向集合。

Debug APK 和 database AndroidTest APK 均为构建检查；本轮没有连接设备、没有安装或运行 Android instrumentation，没有真实平台账号导入/联网播放/实际切源/性能测量。CI 结果另行记录，不将上轮绿色当成本轮结果。酷我仍仅元数据目录，完整音频未接入。
