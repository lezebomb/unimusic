# Phase 2W：分来源搜索耗时与明确超时分类

日期：2026-10-28。每源快照新增本次尝试的单调时钟耗时，包含许可排队及元数据处理/发布，重试时只清当前被请求来源的计时；未请求平台保留上一批次证据。计时只在内存，不记录查询、账户、URL或Cookie，不上传。

聚合状态区默认收起，使用“查看各来源耗时”展开已经完成来源的本批次秒数；明确说明这不包含音频校验和播放。支持中英资源。未完成的来源仍显示加载，不伪造耗时/成功。

SocketTimeoutException明确显示超时，酷我自身6秒窗口结束使用类型化TIMEOUT，不再当普通网络错误。权限拒绝/开关/通用网络错误各自保留，预算没有延长，也没有增加后台重试。

实际执行7项JVM：新增1个虚拟时钟场景覆盖20ms许可排队后25ms socket失败与4ms单源恢复、保留健康来源计时；相关预算/取消/健康分页等5项与酷我普通请求1项。全通过，Debug成功，边界通过。数值仅为注入调度，不是线上延迟；[证据](evidence/2026-10-28/phase2w/validation.json)含XML/APK哈希。新UI未安装、没有真实线上计时、账号或音频验收。
