# Phase 2A：临播音源获取与严格候选筛选

日期：2026-10-26。用户要求优先解决音源，暂缓 Phase 1C 导入界面。本轮直接改造 Android 播放后台中的网易云→本地→B 站备用源链路，未另建转发/解锁服务器。Room 保持 v22，无数据库迁移。

## 已实现行为

1. 网易云使用原有账号、原有 EAPI 播放地址和音质降级顺序。新增可取消请求，绑定请求开始时的会话，换号后不返回旧账号的地址；保留已有的一次 CSRF 预热。单个请求最多 3 秒，主源音质尝试共用 8 秒预算。此处为解析预算，不是实测首声延迟。
2. 主源无法提供完整音频时，尝试已开启的本地兜底，然后尝试已开启的 B 站自动备用源。网络异常、需要登录、无地址等情况也能进入备用链路；不再只对试听/无权限响应启用兜底。原有试听提示及独立试听缓存键仍保留，未把试听标成完整音频。
3. 本地文件继续走原有 URI 授权与可读性检查。相同歌词匹配 ID 仅用于排序，还必须满足曲名、歌手、版本和已知时长；缺少时长或版本冲突时不自动接受。保留原本地 8 秒时长容差。
4. B 站搜索使用原曲名和歌手，按已有相关性分数排序；分数不再充当自动接受阈值。逐个检查真实视频详情和分 P，必须满足规范化曲名、歌手文本证据、相同版本标记和 4 秒内时长差。多分 P 必须检查自身标题、cid 和时长，多个分 P 同时满足时拒绝自动选择。
5. 备用源通过普通播放接口解析，发送 `try_look=0`，不走 HTML 备用解析。检查实际响应中的预览/DRM 标志和完整时长，只选择接口返回的可用音轨；没有合法可用流就失败。没有伪造会员身份、解密 DRM 或新增代理地址。
6. Flow 候选发现和解析共用 10 秒预算，每候选最多 3 秒，首个成功结果直接返回，不再等待两个备用地址。网易云外层不再重跑整条多源链路五次；其他平台的原有重试不变。父协程取消会取消 HTTP Call，并继续向上传播。
7. 网络/超时/URL 失效等暂时失败按原歌曲和候选 ID 冷却 60 秒，最多 256 项；真正播放失败和卡顿刷新也会避开刚失败的自动备用源。手动刷新、旧进度恢复或离线缓存失败不误伤在线源。成功候选元数据最多保留 10 分钟、128 项，使用前重新校验、重新解析地址，不持久化临时 URL。
8. 继续使用原歌曲、歌单和队列身份；不同 B 站分 P 和音轨使用原有独立缓存键。移除了此次路径中的完整网易云响应、签名地址和本地 URI 日志。

## 实现入口

- `modules/playback/logic/.../policy/source/RecordingMatchPolicy.kt`：文本规范化、版本冲突和独立元数据门槛。
- `modules/playback/logic/.../policy/source/PlaybackSourceResolver.kt`：来源资格、失败类型、总/单源预算、取消与冷却。
- `modules/playback/runtime/.../resolver/netease/`：本地门槛、B 站详情/分 P 与媒体响应校验、候选状态及实际备用源适配。
- `modules/playback/runtime/.../url/NeteasePlaybackUrlResolver.kt`：从原 URL 扩展拆出的主源和备用链路，避免继续扩大超长文件。
- `modules/platform/.../netease/api/client/NeteaseClient.kt` 及 B 站 client/session：复用现有账号和协议，接入可取消 OkHttp。
- `.github/workflows/unimusic_smoke.yml`：新增 playback 触发路径及上述定向检查；保留原迁移 CI。

## 明确边界与后续

本轮是现有 SongItem 播放路径的保守筛选与获取能力。标题、上传者文本、时长和接口返回流都不能单独证明发行录音身份、上传版权或平台允许脱离官方播放器播放。当前资格开关沿用用户的显式设置，服务端仍决定账号可访问音轨；尚未建立独立、经审核的来源权利/能力注册表，不能把这个开关称为版权核验。

目前只接入已有本地和 B 站备用源，未新增平台，不承诺商业曲库全部免费。没有证据或多个候选相近时保持失败/原有试听降级，不自动播放另一版本。原有手动 B 站和 YouTube 播放路径保持原设计。

下一子阶段优先补充可持久的同录音匹配/用户确认与拒绝记录、明确的来源能力状态，再把解析入口迁到 `SourceResolver(unifiedSongId)`。统一搜索聚合、人工标注数据集、实际账号覆盖率和完整失败切源闭环仍待完成。不能把本轮 40 个合成/协议测试当作 Phase 2 全部验收。
