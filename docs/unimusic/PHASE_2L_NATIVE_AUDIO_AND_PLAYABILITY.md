# Phase 2L：QQ / 酷我正常音频与可播性排序

日期：2026-10-27，Asia/Shanghai。基线 `cdb15b90`，Room 保持 v23，没有修改冻结迁移或执行 destructive migration。

## 实现

- **酷我**：新增独立匿名 `KuwoAudioClient`，按当前官网流程建立会话、生成普通请求头、读取最新歌曲详情，再请求 `playUrl`。每个响应可能更新匿名 Cookie，整段流程用可取消 Mutex 串行维护会话。只有明确的 `isListenFee=false`、`online=1`、`cannotOnlinePlay=0` 才请求音频；缺字段或付费拒绝都不放行。只接受 HTTPS 酷我 CDN MP3。
- **QQ**：新增正常 `music.vkey.GetVkey/UrlGetVkey` 客户端和聚合搜索入口。获取最新详情及 media MID，只请求完整标准 MP3 `M500`；绑定返回的精确 MID、文件名、成功码和预期 HTTPS CDN。拒绝试听文件、加密媒体、非预期地址。未登录与已登录但无权限分开返回，不把保存账号等同于有权播放。
- QQ 凭证只在已有安全仓库和 QQ 协议层之间使用；取流捕获账号修订，退出/换号期间返回的旧地址作废。新增退出与音频响应竞态检查。凭证不进入第三方服务、歌曲映射、同步或备份。
- 两源接入能力登记、来源菜单、显式校验、统一 UUID 临播，以及搜索结果的播放按钮。Catalog 搜索结果仍与原 Song 下载/批量队列分开；点击播放才构造精确原生身份。两个来源的地址均按在线播放处理，绕过音频磁盘缓存、预取和链接分享；下载入口及后台来源分派同时阻止将新平台 ID 解释成网易云 ID。
- 本地与新来源的 UUID / 映射使用现有增量表。自动成功的 QQ / 酷我来源纳入既有 v2 映射和精确 SQL 查询，保留 24 小时 TTL、目标指纹、人工决策和失效逻辑；不持久化临时 URL。

## 自动匹配与等待预算

自动备用源仍由用户的播放源兜底开关控制。原站正常时优先原站；已确认偏好沿用既有规则。原站失败后，先复用成功映射与本地匹配，再让 QQ / 酷我两个正常 Provider 并发发现与取址，首个合格完整地址返回后立即取消另一条。既有 B 站兜底继续使用剩余预算。

- 全程继承既有地址解析共享 8 秒预算，不叠加多个完整超时；这不包含播放器启动/首声时间。
- 新发现阶段至多 3.8 秒，每源搜索至多 1.2 秒、候选取址至多 2.6 秒；每个平台最多一个无歧义候选。
- 自动选择要求歌名、歌手、版本类型和时长均合格。时长容差仍为在线 4 秒；不因某个接口失败而放宽到翻唱、现场、变速或片段。
- 同源多个合格 ID 只有在专辑能唯一消歧时才自动选择；否则保留手动候选，不取第一条凑数。用户拒绝、账号变更、断网及开关变化在返回时复核。
- 失败候选沿用冷却，自动成功后保存精确来源映射，下次重新解析该来源 ID。

这些是保守元数据规则，不是声纹识别，也没有经人工原唱标注集校准；同名同歌手同专辑的错误元数据仍可能存在。歌手别名与不同发行版本可能被保守拒绝。

## 列表排序

聚合搜索先展示已返回的结果，不等待全部取流。每次查询最多异步校验六个原生候选（每源最多三个、每源总计 4.5 秒、单候选最多 1.8 秒；成功即停止）；歌名/歌手相关性与版本仍优先，在相近相关性层中按地址已校验、未校验、失败排序。首条失败继续检查后面的候选；不会把可取址的 Live 放到同等相关的原版前面。搜索与详情统一解码 HTML 转义，避免 `&apos;` 等字符导致歌手名误判。结果标识为“音频地址已校验”，不宣称已实际播放。

来源菜单同样先执行录音门槛与人工拒绝，再将新近可取址候选上移。可播性观察只在内存保留 2 分钟，账号变化/新查询会失效；播放前仍重新取址。排名在 Default 调度器执行，并复核查询代次及当前列表，避免旧结果覆盖新搜索。

## 接口证据与限制

协议依据为当前 [酷我官网](https://www.kuwo.cn/) 的普通网页请求及实际响应，以及 [QQMusicApi 项目的普通 Vkey 接口定义](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/song.py)；未使用其加密媒体处理，也未使用伪造车机/VIP或会员、DRM 破解链路。

QQ 真实账号正向取流、平台登录交互、更多歌曲完整播放、跨网络耐久和首声/故障切源分位数仍需分别验收。当前不承诺所有商业曲目免费，也不把一次样本取址或解码成功扩展成全曲库结论。
