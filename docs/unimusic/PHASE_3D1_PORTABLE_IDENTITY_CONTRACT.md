# Phase 3D.1：精确身份同步契约

日期：2026-10-28。已实现独立模型、纯合并和严格编码后台；未接生产网络或应用Room数据，不是完整统一库同步上线。

## 行为

- 只有公开平台精确四元来源身份一致才建立别名，canonical UUID取稳定最小值，原UUID和来源证据保留。相同歌名/歌手不合并，B站不同分P不合并，未解析分P拒绝导出。
- 元数据/删除是带设备dot与已观察上下文的因果寄存器。离线并发删除优先，修改分支保留供后续冲突界面处理；已经观察删除后的显式恢复才允许重新存活。没有用墙上时钟选胜者。
- 每设备dot必须从持久单调计数器分配；context只包含该身份/已知别名的已观察历史，不能复制无关歌曲的全局时钟。当前阶段只提供契约，持久分配器尚待下一子阶段。
- 合并先验证dot重复内容、同设备分叉与已知上下文传递性，再压缩因果前沿。来源别名证据在删除后保留，避免旧UUID回写复活。并发元数据没有自动判定用户正确选择，保留全部前沿；临时展示值以稳定设备顺序确定。

## 协议和隐私

`UnifiedIdentityDataset`使用独立schema=1/capability，未添加到旧SyncData。白名单仅歌曲元数据、UUID、公开平台歌曲ID和因果上下文；不含账号、路径、Cookie、下载/音频地址、权限或可播状态。未知provider/local/legacy、未解析context不导出。

编码/解码有8MiB、5万身份/修订、64设备、深度与字段长度限制。未知schema/capability/字段、重复JSON字段、非法UTF8和没有明确协议头的文档拒绝；删除metadata必须显式null，缺失字段不默认为删除。超限拒绝，不截断数据。
