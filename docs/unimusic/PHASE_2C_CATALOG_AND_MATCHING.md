# Phase 2C：酷我目录后台与自动候选优化

日期：2026-10-26。接续 `7022b9b6`；其 [聚合搜索 CI](https://github.com/lezebomb/unimusic/actions/runs/40274273540) 已成功。用户要求主代理继续后端，子智能体分析本地样本；已按此分工完成。

## 普通音源接口与明确能力

- 子智能体使用更新后的 REA 6.8.0 CLI，确认样本的网易云元数据→关键词→酷我搜索适配链。事实、输入哈希、版本和静态覆盖见 [APK 审计](APK_SOURCE_AUDIT.md)。没有执行样本、连接其中的账号、调用未知代理或移植破解 Hook。
- 新增 `MusicCatalogProvider`、`CatalogTrack`、`CatalogSearchPage`，返回独立来源键与统一元数据，明确区分目录发现和播放能力。
- `KuwoCatalogProvider` 独立实现匿名 HTTPS 普通搜索：`search.kuwo.cn/r.s`，仅发送关键词、music 类型、页码、数量与数据格式参数。不发送账号、Cookie、签名、会员/版权筛选参数或第三方代理地址。
- 支持正整数歌曲 ID、名称、歌手、专辑、秒转毫秒、常见 HTML 实体与字面量 `u0026` 清理；重复 ID 去重，非法条目不改变原分页水位。返回官方页面候选 URL，但未对页面播放/跳转进行设备验收。封面接口未核实，没有猜测或填入音频链接。
- Provider 总预算 6 秒、响应最多 2 MiB，HTTP 和协程可取消。自身超时转为 I/O 失败，父协程取消仍传播，避免日后聚合时把一个来源的超时变成整个请求取消。
- 已装配 `AppContainer.kuwoCatalogProvider`，供后台调用。其能力固定为 **METADATA_ONLY**，不因 `PAY=0`、`COPYRIGHT=0` 或搜索命中而标成有权播放。
- **酷我尚未接入聚合 UI、播放器或下载器**。当前聚合入口仍是本地/网易云/B 站/YouTube 四个已有来源；不能把酷我数字 ID 交给网易云播放器路径，也不宣称已经取得酷我完整音频。

## 自动找到更合适的候选

样本只在前五条中按约 5 秒时长差选首个，没有则取第一条。这会把同长度的翻唱、现场或其他歌曲当作原曲，不直接移植。

新增 `RecordingDiscoveryRanker` 并接入实际 B 站自动备用源链路：

1. 在取前六条详情候选前，排除已经明确出现的不相符版本标记，避免高文本分的翻唱/现场占满窗口。
2. 优先完整元数据门槛已通过的候选，其后分别比较曲名、歌手、已知时长差，最后才用原文本相关性打破相同条件。
3. 候选去重、稳定排序；搜索阶段缺少版本/时长的信息保留给详情判断，不把“信息未知”当成已匹配。
4. 真正播放仍须通过原有详情/分 P 歧义校验、版本/歌手/时长门槛和正常播放接口访问检查。排序不放宽这些条件，不增加会员/DRM 绕过，不随意选择第一条失败替代。

这改善了真实自动兜底的候选发现顺序，没有建立经标注校准的匹配概率，也没有完成跨平台可信录音合并或统一 UUID SourceResolver。

## 实际验证

- 本机只读访问普通酷我 HTTPS 搜索，HTTP 200，查询 Beethoven 返回 5 条元数据。第一轮严格 JSON 解析失败，确认响应为单引号对象字面量；第二轮用数据字面量解析，未执行 JavaScript。Android 代码使用 JSONObject 的兼容解析，并有对应夹具检查。该探测没有请求音频、登录账号或验证完整播放。
- 9 个定向 JVM 测试通过：候选排序 3、原严格录音门槛 3、酷我目录接口/解析/参数 3。响应实体夹具和超时处理修正后，仅重跑酷我 3 个检查；未运行全量套件。
- Debug APK 与模块边界检查通过；平台依赖边界也纳入本轮验证。首次平台依赖检查暴露此前导入/取消路径未登记的精确类型；逐项核实后补登记具体类，没有新增全包通配授权或放宽边界阈值。
- 证据、命令、APK 大小与哈希见 `evidence/2026-10-26/phase2c/`。本轮未安装 APK、连接手机/模拟器，未做真实账号、App 联网搜索、自动切源或性能/功耗验收。

Room 保持 v22，没有迁移或删除用户数据。原始样本、反编译代码、工具 JAR 和 REA 完整 bundle 保存在忽略的本机 build/ 或临时目录；仓库只保存无凭据的静态报告、摘要与哈希。
